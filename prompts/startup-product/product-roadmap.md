# 把路线图绑定证据门槛

[分类目录](README.md) · [总目录](../../README.md)

ID：`startup-product/product-roadmap`  
状态：**待验证 / untested**

## 输入变量

| 变量 | 填写说明 |
| --- | --- |
| `requests` | 候选功能 |
| `evidence` | 已知证据 |
| `capacity` | 资源 |

## 复制模板

将下方变量替换为你的材料。不要将示例中的演示数据用于真实报告。

```text
requests：{{requests}}
evidence：{{evidence}}
capacity：{{capacity}}

按核心价值、证据强度、技术依赖和维护成本排序。路线图使用现在、下一步、待验证三档，为每项设置进入开发的证据门槛与停止条件。明确不承诺未经估计的日期，保留可靠性与维护预算。
```

## 示例输入

```json
{
  "requests": "团队空间、浏览器插件、本地模型、多语言、引用核查",
  "evidence": "8 位测试者里 5 位遇到引用核查困难；其余未验证",
  "capacity": "一个月，两名开发者"
}
```

## 预期输出

有依据的路线图和每项验证门槛。

## 适用与边界

适合避免需求堆积的小团队。

路线图应随证据更新，不是交付保证。

## 来源与验证

为本合集原创编写，AI 辅助起草；未复制外部提示词。

未经模型运行验证；示例输入用于说明填写方式，不代表已获得输出。
