# 把首版缩到一个闭环

[分类目录](README.md) · [总目录](../../README.md)

ID：`startup-product/mvp-scope`  
状态：**待验证 / untested**

## 输入变量

| 变量 | 填写说明 |
| --- | --- |
| `product` | 产品想法 |
| `resources` | 团队与时间 |
| `core_job` | 最关键用户任务 |

## 复制模板

将下方变量替换为你的材料。不要将示例中的演示数据用于真实报告。

```text
product：{{product}}
resources：{{resources}}
core_job：{{core_job}}

围绕一个完整任务定义首版输入、核心处理、输出与失败处理。将功能分为必须、后续和删除，说明每项对价值验证的作用。给出用户流程、数据边界、验收和埋点；不以堆模型或功能数量作为成功指标。
```

## 示例输入

```json
{
  "product": "科研助手：读论文、查文献、写笔记、生成实验计划",
  "resources": "两名开发者，四周",
  "core_job": "上传论文后生成可追溯精读卡并导出"
}
```

## 预期输出

MVP 范围、任务闭环与四周验收计划。

## 适用与边界

适合资源有限的产品初版。

估期需开发者评审，不能保证四周上线。
