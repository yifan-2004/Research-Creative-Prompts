# 把用户反馈转成产品决策

[分类目录](README.md) · [总目录](../../README.md)

ID：`startup-product/support-triage`  
状态：**待验证 / untested**

## 输入变量

| 变量 | 填写说明 |
| --- | --- |
| `feedback` | 反馈集合 |
| `context` | 阶段 |
| `resources` | 可用资源 |

## 复制模板

将下方变量替换为你的材料。不要将示例中的演示数据用于真实报告。

```text
feedback：{{feedback}}
context：{{context}}
resources：{{resources}}

按阻断核心任务、信任损害、频率、影响范围和修复成本分类。对每项提出需要补采的证据，优先修复核心可靠性而不是简单投票。输出两项建议及暂缓理由，避免把单个大声反馈当普遍需求。
```

## 示例输入

```json
{
  "feedback": "F1 导出失败；F2 想要十种主题色；F3 来源页码有误；F4 希望支持团队",
  "context": "首版封闭测试，核心价值是可追溯摘要",
  "resources": "下周只能完成两项改动"
}
```

## 预期输出

反馈分级表、优先事项与回复草稿。

## 适用与边界

适合小团队处理反馈。

频率与成本未知时优先级只能是暂定。

## 来源与验证

为本合集原创编写，AI 辅助起草；未复制外部提示词。

未经模型运行验证；示例输入用于说明填写方式，不代表已获得输出。
